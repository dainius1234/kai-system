1. THE ROOT, AND IT IS NOT WHAT THE E2 SUMMARY IMPLIED
   The census package is NOT internally source-unbound. Its own
   runner, run_census.py, is rigorously subject-bound:
     - the ref is resolved to an IMMUTABLE 40-hex commit id ONCE;
     - materialise() REFUSES anything that is not a 40-hex oid;
     - `git archive <commit>` extracts the tree into a fresh dest;
     - dest is re-inited and committed, so HEAD == the subject;
     - the materialised ls-tree is reconciled against the ORIGINAL
       repository's ls-tree, and a mismatch is an R11 ABORT;
     - cal_subject_binding.py exists solely to prove the
       resolve-once discipline against a moving ref.
   `tracked_md(repo)` reading HEAD and `(repo/fn).read_text()` are
   therefore CORRECT INSIDE THAT MATERIALISED SUBJECT. HEAD == the
   subject and the tree is clean BY CONSTRUCTION. That is the
   contract those functions were written against.

   THE ROOT IS THAT PASS A BYPASSES THAT HARNESS. passa.build
   imports the census LIBRARY -- docgraph, opscan, claims -- and
   calls it against the LIVE repository, outside materialise().
   The precondition that makes HEAD-and-filesystem correct is
   neither ESTABLISHED nor CHECKED.

     S1-a  PRECONDITION NOT ESTABLISHED. No materialisation. The
           subject is never extracted, so nothing makes HEAD equal
           the subject or the tree clean.
     S1-b  THE PRECONDITION IS HALF-CHECKED, AND THE HALF THAT IS
           MISSING IS THE ONE THAT BITES. passa.main() L602-604
           ASSERTS HEAD == subject and aborts otherwise, and
           run_h2_v12.main() L321-323 repeats it. NOTHING anywhere
           checks that the WORKING TREE IS CLEAN. So a moved HEAD
           is refused loudly, and a dirty tree is not noticed at
           all -- and it is the dirty tree that silently changes
           the bytes analysed.
           THIS CORRECTS THE FIRST DRAFT OF THIS INVESTIGATION,
           which asserted the precondition was unchecked. It is
           not. The AST binding-site table below is what surfaced
           passa.py L602, and the claim was corrected before this
           report was banked.
     S1-c  THE GATE IS ON THE ENTRYPOINT, NOT ON THE MEASUREMENT.
           build() carries no gate of its own, so any future caller
           importing passa as a library -- which is exactly how
           Pass A imports the census -- gets no protection. That is
           the same shape as S1-a one level up.

3. THREE INDEPENDENT BINDING SOURCES IN ONE ROW
   enumeration  repository HEAD
   bytes        the working filesystem
   history      the requested subject  (correctly bound)
   They can disagree independently and in any combination, which
   is exactly Kai's question 4: YES. A row can carry history from
   one commit, a file list from a second and bytes from a third.

7b. PRODUCTION REACHABILITY — WHICH OF THESE CAN ACTUALLY HAPPEN
   produced output, rc=0                : 1 of 5
     A  worktree edited after the commit
   REFUSED by the existing HEAD gate    : 3
     B  subject != HEAD  -- R11 ABORT
     D  new tracked file at HEAD, absent from the subject  -- R11 ABORT
     E  rename after the subject commit  -- R11 ABORT
   STOPPED, but by an unhandled exception rather than a gate: 1
     C  tracked file deleted from the worktree  -- Traceback (most recent call last):
   The three buckets are kept apart deliberately: a gate refusing
   and a program crashing are not the same outcome, and calling
   both 'refused' would overstate what the code does.

   THIS IS THE FINDING THAT MATTERS, AND IT IS NARROWER AND
   SHARPER THAN 'THE CENSUS IS SOURCE-UNBOUND'.
   The subject != HEAD cases (B, D, E) CANNOT occur in production:
   passa.main() refuses them with an R11 ABORT before measuring.
   What reaches production is the WORKING-TREE DIRTINESS class,
   because nothing anywhere checks it:
     A  dirty tree, HEAD == subject -> SILENT DRIFT, rc=0, a full
        result file written, witnesses taken from uncommitted bytes
        and stamped with the subject's identity. THIS IS THE REAL
        REALISED EXPOSURE.
     C  a tracked file deleted from the tree -> an UNHANDLED
        FileNotFoundError. It does stop, but through a traceback
        rather than an R11 abort naming the unmet prerequisite,
        so it fails loudly and UNGRACEFULLY (R11's own standard:
        abort at the prerequisite boundary and say which one).

8. DETACHED HEAD — Kai's question 11
   subject ba4dd2ed2e59  HEAD now ba4dd2ed2e59  equal=True
   analysed ['docs/alpha.md', 'docs/beta.md']
   A detached HEAD is not a separate mechanism. It changes WHERE

   Checking out the subject makes the run correct BY ACCIDENT --
   the same accident that made the E2 measurement correct.

9. SYMLINKS AND TRAVERSAL — Kai's question 12
   tracked .md at the subject      ['docs/alpha.md', 'docs/beta.md', 'docs/escape.md', 'docs/link.md']
   docs/link.md bytes analysed     38
   docs/escape.md bytes analysed   10
   git stores a symlink as a blob holding its TARGET PATH, so the
   subject's own bytes for a link are the path string. Reading it
   from the filesystem FOLLOWS the link instead, and for a link
   pointing outside the repository the bytes analysed come from
   OUTSIDE THE SUBJECT ENTIRELY -- a binding ambiguity that no
   commit id can describe. A tree-bound read would return the
   link's own blob and could not leave the repository.

14. SMALLEST PLAUSIBLE REPAIR PRINCIPLE (proposal, NOT implemented)
   Do not rewrite the census. The HEAD half of the precondition is
   already gated; CLOSE THE HALF THAT IS NOT. Two candidate shapes,
   and they answer DIFFERENT questions:
     (i)  MATERIALISE. passa.build extracts the subject with the
          existing run_census.materialise() and analyses the
          materialised tree. Reuses the proven, calibrated code
          path. Cost: an extraction per run.
     (ii) GATE THE WORKING TREE. passa.main() already asserts
          HEAD == subject; add the missing clean-tree assertion and
          worktree, and ABORTS otherwise. Cheap, and it converts
          silent drift into a loud refusal. It does not let a
          non-HEAD subject be analysed.
   KAI'S QUESTION 10, ANSWERED PRECISELY: a non-HEAD frozen subject
   CANNOT be analysed today -- and the reason is a CORRECT REFUSAL,
   not a drift. passa.main() aborts. The capability is absent, not
   broken. Only shape (i) would add it.
   (ii) CLOSES THE REALISED EXPOSURE -- demonstration A -- at the
   cost of one assertion. (i) additionally ADDS a capability that
   does not exist today: analysing a subject that is not HEAD.
   They are not competing repairs for the same defect; (ii) fixes
   what is broken and (i) extends what is possible. Demonstration C
   argues for one more thing under either shape: a clean-tree gate
   would turn that traceback into a named prerequisite abort.
   THIS IS A DESIGN CHOICE FOR KAI, NOT SETTLED HERE.
   FILES THAT WOULD NEED MODIFICATION IF LATER AUTHORISED:
     passa.py    only, under either shape
   AND NOTHING ELSE. The census package would be IMPORTED, not

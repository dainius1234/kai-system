3. SYMLINK BEHAVIOUR THROUGH THE FULL MATERIALISATION PATH
   git archive -> tar extraction -> Path.read_text()
   This is the path a materialisation repair would introduce, so

   C_broken
     git mode                 120000  (120000 = symlink)
     blob content (the commit)'no_such_file.md'
     extracted as a symlink   True  -> no_such_file.md
     read_text() FAILED       FileNotFoundError
     INGESTS BYTES NOT IN THE COMMIT: False

   ANSWER TO KAI'S QUESTION: YES for A and B. git stores a symlink
   as a blob whose CONTENT IS THE TARGET PATH. Extraction restores
   a real symlink, and read_text() FOLLOWS it, so the bytes
   analysed are the target's, never the blob's. For B the target
   lies OUTSIDE the materialised subject entirely, so the analysed
   bytes are not represented by the frozen commit in any form. C
   fails with an exception rather than drifting.
   THEREFORE MATERIALISATION ALONE IS NOT CLOSURE. S1 closure
   requires an explicit symlink policy. The measured options:
     P1  REJECT any analysed path whose tree mode is 120000.
         Fail-closed, smallest, and loses whatever a symlinked
         document was contributing.
     P2  TREAT THE BLOB AS THE EVIDENCE -- read the object, not the
         filesystem. The blob is the target path string, which is
         what the commit actually contains. Source-bound by
         construction and it cannot leave the repository.
     P3  RESOLVE INSIDE and reject escapes. Larger, and it still
         analyses bytes the link does not itself contain.
   MEASURED, NOT PREFERRED: P2 is the only one of the three that is
   source-bound BY CONSTRUCTION rather than by a check that can be
   forgotten. P1 is the smallest. THE CHOICE IS KAI'S.

   at the measurement boundary, not two at the entrypoints.

5. REPAIR OPTIONS RANKED BY WHETHER THEY CLOSE THE ROOT
   The root is an UNENFORCED PRECONDITION AT THE MEASUREMENT
   BOUNDARY, so an option closes it only if the invariant is true
   AT build(), for every caller, including symlinks.

   R1  GATE IN build(): assert HEAD == subject AND clean worktree,
       before the first census call. Abort with a named
       prerequisite.
       safety      YES for A and C, at build(), all callers
       capability  NO -- non-HEAD subject still unanalysable
       symlinks    NO -- a clean tree still contains symlinks that
                   read_text() follows
       CLOSES THE ROOT? PARTIALLY. Closes the realised exposure.

   R2  MATERIALISE in build() via the census's proven materialise()
       safety      YES for A, C, and for subject != HEAD
       capability  YES
       symlinks    NO -- section 3 proves extraction plus
                   read_text() still escapes the commit
       CLOSES THE ROOT? NO, not on its own.

   R3  R2 + AN EXPLICIT SYMLINK POLICY (P1 or P2)
       safety YES · capability YES · symlinks YES
       CLOSES THE ROOT? YES.

   R4  R1 + AN EXPLICIT SYMLINK POLICY
       safety YES · capability NO · symlinks YES
       CLOSES THE ROOT AS IT IS REALISED TODAY, and leaves the
       non-HEAD capability absent -- which is a CORRECT REFUSAL,
       not a defect.

   SMALLEST ROOT-CLOSING MECHANISM, not the smallest line diff:
   R4 if the programme accepts that a non-HEAD subject stays
   unsupported; R3 if that capability is wanted. Both need the
   symlink policy, and section 3 is why. THE CHOICE IS KAI'S.
